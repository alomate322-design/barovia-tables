# Кости Баровии — расширение для Owlbear Rodeo

Второе, отдельное расширение (не связано с Ravenloft Music). Это точная копия
твоего Artifact «Кости Баровии» — все случайные таблицы книги, маршрутный
калькулятор с автобросками столкновений, трекер боя (инициатива/хиты),
шкала «Страд следит», погода/луна и бестиарий с кликабельными чарниками —
упакованная как popover-расширение Owlbear Rodeo, вместо отдельной вкладки
браузера.

## Важно: это НЕ синхронизируется между игроками

В отличие от Ravenloft Music, у этого инструмента **нет** обмена состоянием
через комнату Owlbear Rodeo — он и в оригинальном Artifact работал точно
так же: все брошенные результаты, трекер боя, счётчик дня похода и т.д.
хранятся только в памяти вкладки/попапа того, кто его открыл, и исчезают
при закрытии. Это осознанное 1:1 повторение оригинала — справочник ведущего,
которым пользуешься только ты. Если в будущем захочешь, например,
синхронизировать трекер боя между твоим и запасным устройством — это можно
добавить отдельно (тем же способом, что и Ravenloft Music, через
`OBR.room.setMetadata`), просто скажи.

## Видимость только для мастера

Owlbear Rodeo не даёт расширениям способа спрятать саму кнопку/значок в
панели инструментов от отдельных участников — расширения включаются на
уровне комнаты и в панели видны всем одинаково (и мастеру, и игрокам). Это
ограничение платформы, обойти его нельзя.

Что расширение делает само — прячет **содержимое**: при открытии попапа оно
проверяет роль через `OBR.player.getRole()`, и если открывший не мастер,
показывает вместо справочника заглушку «этот справочник — личные заметки
мастера». Раньше эта проверка была устроена так, что при любой ошибке
(например не загрузился скрипт Owlbear SDK) содержимое по умолчанию
оставалось видимым — то есть при сбое игрок мог увидеть реальные заметки.
Переделал на обратную логику: теперь справочник **скрыт по умолчанию** и
показывается только после успешного подтверждения роли «GM» — если
проверка не прошла, зависла или чего-то не хватило, попап так и останется
с заглушкой (в том числе у тебя самого — в этом случае просто обнови
страницу расширения).

Итог: кнопка в панели видна всем участникам комнаты (так работает Owlbear
Rodeo), но открыв её, игрок увидит только заглушку — реальные таблицы и
трекер показываются исключительно тому, у кого роль GM в этой комнате (и
игрокам с персональным доступом — см. ниже).

## Починено: справочник иногда не открывался даже у настоящего мастера

Нашёл и поправил баг в самой проверке роли. Раньше код, который спрашивает
Owlbear "какая у меня роль", стартовал в самом низу страницы — то есть
только ПОСЛЕ того, как браузер разберёт и выполнит весь остальной скрипт
(3000+ строк). На медленной сети это иногда не укладывалось в 8-секундный
таймаут защиты — и справочник оставался с заглушкой даже у тебя самого
(лечилось обновлением страницы, но это баг, а не ожидаемое поведение).

Теперь этот запрос стартует в `<head>`, параллельно с разбором всей
остальной страницы, тем же способом, что и в двух других расширениях
кампании — там эта проверка ни разу не подводила. Заодно увеличил
таймаут-подстраховку до 15 секунд на случай совсем медленной сети.

**Нужно перезалить `index.html`** — единственный файл этого расширения.

## Доступ для второго ГМ (со-ГМ)

Owlbear Rodeo не даёт роли "со-ГМ" — второй мастер почти всегда заходит в
комнату как обычный игрок (вкладка "Players" в его профиле), и до сих пор
для него это означало ту же заглушку, что и для игроков партии.

Теперь у настоящего мастера (роль GM) в правом верхнем углу справочника
появляется маленькая кнопка "👥" — она открывает список игроков, которые
сейчас в комнате. Отметь галочкой второго ГМ и нажми "Сохранить": список
сохраняется в room metadata комнаты, и с этого момента отмеченный игрок
видит справочник полностью — те же таблицы, трекер боя и всё остальное,
что и настоящий мастер, — хотя по роли Owlbear Rodeo он остаётся обычным
"Player". Если он уже держит попап открытым в момент, когда ты его
отметил, — справочник откроется сам, без перезахода. Отменить доступ —
снять галочку и снова нажать "Сохранить".

Список игроков в этой кнопке подтягивается из тех, кто сейчас реально
находится в комнате — если второго ГМ там ещё нет, кнопка покажет об этом
и предложит открыть её позже, когда он зайдёт.

## Файлы

- `manifest.json` — манифест расширения.
- `icon.svg` — иконка (кубик к20).
- `index.html` — вся страница целиком (разметка + стили + скрипт), без
  внешних зависимостей, кроме шрифтов Google Fonts.

## Деплой на Render (шаги те же, что и для Ravenloft Music)

1. Зайди на github.com, создай **новый** репозиторий (можно приватный),
   например `barovia-tables`.
2. Залей туда все три файла из этой папки (`manifest.json`, `icon.svg`,
   `index.html`) — через «Add file → Upload files» или `git push`.
3. На render.com → **New → Static Site** → выбери этот репозиторий.
   - Build Command — оставь пустым.
   - Publish Directory — `.` (точка, корень репозитория).
4. После деплоя Render даст адрес вида `https://barovia-tables.onrender.com`.
5. Проверь в браузере, что манифест открывается:
   `https://barovia-tables.onrender.com/manifest.json` — должен вернуть JSON,
   а не ошибку.
6. Если после этого при установке в Owlbear Rodeo будет ошибка
   «Failed to fetch» — зайди в Render → твой сайт → **Settings → Headers**
   → добавь правило: Path `/*`, Name `Access-Control-Allow-Origin`,
   Value `*`. Это тот же самый CORS-фикс, что понадобился Ravenloft Music.

## Установка в Owlbear Rodeo

1. Extensions → Install extension → вставь ссылку на `manifest.json` из
   шага 5 выше.
2. Появится вторая кнопка — «Кости Баровии», рядом с Ravenloft Music.
3. Открывается popover пошире (под макет оригинальной страницы) — внутри
   него всё работает как в артефакте: разделы по якорям сверху, кнопки
   «Бросить»/«Рассчитать», клики по именам монстров открывают модалку с
   полным чарником.

Если что-то не отобразится или будет ошибка — как обычно, скриншот/консоль
(F12) сюда, разберусь.
